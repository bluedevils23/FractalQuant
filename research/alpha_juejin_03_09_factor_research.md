## 2. 第3篇：非线性因子线性化和失效纠正

### 原文公式和方法

原文 pp. 4-10 先构造高、低价格区间的快照成交笔数占比、成交量占比和平均每笔成交量，再针对分组收益不单调的问题做转换。分组收益在过去 N 日估计，因子截面先转为百分位数；在边界、收益最大点和最小点之间做分段线性插值。典型转换为：

```text
x_transform = r_top + (r_max-r_top)/(x_max-x_top) * (x-x_top), x > x_max
              r_max + (r_min-r_max)/(x_min-x_max) * (x-x_max), x_min < x <= x_max
              r_min + (r_bottom-r_min)/(x_bottom-x_min) * (x-x_min), x <= x_min
```

原文还比较线性插值、分段线性近似、多项式拟合和分段线性回归，并以 5 组、60 日历史窗口为示例。其主要收益是改善分位组合单调性和多空可交易性，未必提升 IC；因此它是**因子后处理/校准层**，不是一个新的 alpha 原子。

“失效因子动态纠正”应理解为按滚动分组收益重估映射，并设置稳定性、样本数和失效标记。不能把全样本未来收益用于当天修正。

### 与本地项目的重合度和建议

| 主题 | 现有实现 | 重合度 | 建议 |
|---|---|---:|---|
| 高频价格区间统计 | `trade_notional_quantile_position_60s`、价格带成交占比字段 | 部分 | 先复用已有字段做校准实验，不重复生成原始量 |
| 截面排序/标准化 | `factor/selector.py`、`factor/fz_base.py` 有通用处理 | 部分 | 增加独立的滚动分组收益映射，不改变原始列语义 |
| 动态失效检测 | 未见针对单因子的分组收益状态机 | 低 | P1 增加监控产物，触发重训或停用，不作为盘中信号 |

推荐实现一个离线 `calibrate_factor_by_rolling_bins` 研究函数，输入因子、未来收益、训练截止日和窗口，输出 `calibrated_value`、节点收益、节点样本数、映射版本及 `factor_date/available_time`。禁止使用当前日期之后的数据；窗口不足、分组空缺、节点重复时输出 NaN 并保留原因码。

验收应比较原始/校准因子的分组单调性、RankIC/ICIR、换手、成本后非重叠组合和样本外稳定性。校准不应以提高样本内 IC 为唯一目标。

## 3. 第4篇：逐笔成交遗憾规避

### 原文公式

原文 pp. 4-9 依赖成交的买卖双方订单号、成交方向、成交价、成交量和当日收盘价。核心因子为：

```text
HCVOL = sum(buy_volume * 1[buy_price > close]) / total_volume
LCVOL = sum(sell_volume * 1[sell_price < close]) / total_volume
HCP   = mean(buy_price * 1[buy_price > close]) / close - 1
LCP   = mean(sell_price * 1[sell_price < close]) / close - 1
```

随后按同一订单号汇总拆单，使用当日平均真实订单成交量划分小单，并限制尾盘 `14:30-14:57`；原文认为“小单+尾盘”增强最明显。这里的 `close` 是日终信息，所以完整日频因子最早 d+1 交易。

### 当前数据边界

本地逐笔适配器在 `stock_orderbook.py` 中主要使用时间、方向、价格和数量，不保留买卖订单号的完整生命周期。因此无法可靠复现拆单汇总、主动方向判定和小单筛选。盘口快照或 1 分钟 bar 也不能替代订单号。

| 候选 | 当前重合度 | 结论 |
|---|---:|---|
| HCVOL/LCVOL/HCP/LCP | 低 | 数据条件满足后可新增独立日频字段 |
| 小单版本 | 低 | 需订单号聚合，固定金额阈值不可直接照搬 |
| 尾盘版本 | 低到中 | 时间窗简单，但仍依赖逐笔成交和准确方向 |
| 当前 trade imbalance/impact | 高但不同语义 | 不能改名冒充遗憾规避；做增量消融 |

P2 的最小数据契约是 `trade_date, ts_code, buy_order_id, sell_order_id, side, price, qty, event_time`，并能审计订单拆分、重复事件和方向字段。输出还应含 `order_id_match_rate`、`small_order_threshold`、`late_session_rows` 和原因码。若订单号缺失，整日不产出该因子。

## 4. 第5篇：ChatGPT 挖掘高频因子

原文 pp. 4-9 用 3 秒十档快照构造买卖盘力量：

```text
BForce  = BVol * (1 - mean_bid_price / price)
SForce  = SVol * (mean_ask_price / price - 1)
BSForce = (BForce - SForce) / (BForce + SForce)
```

其中 `BVol/SVol` 是盘口买卖量，`price` 为参考价，日内快照再求均值形成日频候选。该逻辑与本地 `book_pressure_wap5`、`orderbook_pressure_60s`、`orderbook_asymmetry_l5`、OFI/MLOFI 在输入和经济含义上高度相邻。新增同义字段会扩大多重共线性，暂无直接注册理由。

可借鉴的是 LLM 生成流程：限定基础变量、单位和算子 grammar，让模型输出公式和金融解释，再通过确定性执行器复算。任何候选仍须通过严格时间切分和与已有盘口因子相关性/增量检验。

## 5. 第6篇：订单簿斜率凸性

### 原文构造

原文 pp. 5-10 先计算十档累计委托量：

```text
Q_k = sum(Q_i, i=1..k)
```

以累计委托量和价格拟合买卖斜率，买方斜率取负号得到正值；买卖差为：

```text
Slope_ab = Slope_a - Slope_b
```

再将档位拆为低档和高档：

```text
Slope_abl = (Slope_al - Slope_bl) / (Slope_al + Slope_bl)
Slope_abh = (Slope_ah - Slope_bh) / (Slope_ah + Slope_bh)
```

斜率凸性以高低档斜率的反向关系合成，刻画订单簿拟合曲线的弯曲程度。原文低档因子信息更强，沪深 300 上斜率凸性多头年化超额约 12.86%，但这只是原文历史口径。

### 与本地因子

本地已有 `book_slope_diff_l5`，属于五档买卖斜率差，只有部分重合；没有明确的高/低档十档分层和凸性列。因此斜率凸性是本批最值得做的 L2 候选，但应先确认原始快照确实有十档价格/数量且档位方向稳定。

建议新增研究列（不直接写入生产 schema）：`book_slope_bid_l5/l10`、`book_slope_ask_l5/l10`、`book_slope_diff_low`、`book_slope_diff_high`、`book_slope_convexity`。对每个快照记录有效档数、价格重复、零量和回归残差；日频均值在 d+1 使用。ETF 必须使用自身盘口并按流动性分层，不套用股票结果。

## 6. 第7-9篇：文本和模型方法

### 第7篇 ChatGLM/LoRA 医药舆情

第7篇核心是领域标签、LoRA 微调、标签迁移和样本外微调流程，依赖医药新闻/公告文本及行业标签。它不是可以直接加入 `factor` 目录的普通量价因子。可借鉴：按领域建立标签体系、冻结基础模型并只微调适配层、留出时间外样本；不能把报告模型的文本情绪分数当作本地已有字段。

### 第8篇 FinGPT 金融论坛情感

第8篇将论坛文本分类为情感并统计发帖数量、情绪占比及变化。项目未确认有带发布时间、标的映射和历史修订审计的 PIT 论坛数据源，因此暂不实现。若以后接入，必须保留原文版本、模型版本、分类概率和可用时间，并将文本日 d 的聚合信号标为 d+1。

### 第9篇多目标、多模型指数增强

第9篇强调多个目标（收益、风险、换手等）和多个模型的低相关合成，属于模型/组合层。当前项目虽有通用 `factor/ml.py`、`factor/combiner.py` 和因子回测工具，但没有被证明等同于原文的面板训练、目标函数和样本外治理。因此只借鉴：模型之间做相关性与稳定性审计、固定时间切分、成本后评估；不新增报告中的模型作为因子列。
